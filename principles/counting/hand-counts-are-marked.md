# A hand count is marked

**Claim:** a count taken by hand is marked as such in the page, listed row by row in a file, and equal to the tally the results record.

- **Grade:** convention, the maintainer's practice, written down for the review; no study tests it.
- **Evidence:** [baseline](../../evidence/case-reports/baseline.md), the rule added to the checklist. Where: [position](../../evidence/case-reports/position.md), condition 3.
- **Check:** `case-hand-counts` (exact): the page says by hand and links hand-counts.csv, and the tally of the file equals the results.
- **Reader styles:** none particular to this genre yet; the reader-ergonomics styles hold.

## What it asks

- A number a program cannot take, such as the questions that reached a person, is counted by a reader.
- The page marks it with the words by hand and names its reader.
- The folder holds hand-counts.csv with one row per item, its kind and where it came from.
- The tally of the file's kind column is the one the results file records.

## Why

- A count by hand is a claim; a count by a program is a check. The reader must see which is which.
- A row-by-row list lets a second reader recount, which the first case could not offer.

## Limits

- The check compares tallies; it cannot say that a row is right.
- One reader, no second check, is the usual state; the case says so in its Data and procedure.
